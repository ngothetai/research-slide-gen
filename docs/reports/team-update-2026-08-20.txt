2. KẾT QUẢ THỰC NGHIỆM CHI TIẾT (GROUND-TRUTH TỪ NOTEBOOK)
================================================================================

Quy trình end-to-end trên tác vụ: "Based on this slide, please generate a slide for the Beijing Liangxiang sector from 2020 to 2022."

• Stage 1 (Hiểu slide & tham số):
  - Parse lệnh: Rút trích chính xác filter `city: 'Beijing'`, `block: 'Liangxiang'`, `start_date: '2020-01-01'`, `end_date: '2022-12-31'`.
  - Data source slide gốc: Rút đúng bảng `beijing_new_house` và các cột `[supply_sets, trade_sets, dim_area]`.
  - Logic hàm (Four-tuple quadruples): Trích đúng dạng `field-constraint` với bin diện tích 20m² (0-300m²).

• Stage 2 (Truy vấn DB + Tính lại + Tóm tắt Fact-Aware):
  - SQL sinh tự động: `SELECT supply_sets, trade_sets, dim_area FROM public.beijing_new_house WHERE city = 'Beijing' AND block = 'Liangxiang' AND date_code >= '2020-01-01' AND date_code <= '2022-12-31'`
  - ReAct Agent: Gọi tool `execute_analysis`, tính toán lại 15 bins diện tích và xuất ra file Excel.
  - Kết luận tự sinh (Fact-aware):
    "From 2020-2022, Liangxiang's core supply-demand area was 100-120m2, with upgraded units centered on 140-160m2."
  - Kiểm chứng độc lập:
    + Max tổng supply + trade: bin `100-120m²` (Supply: 247, Trans: 183) -> Khớp chính xác kết luận.
    + Max phân khúc diện tích >= 140m²: bin `140-160m²` (Supply: 174, Trans: 142) -> Khớp chính xác kết luận.

• Stage 4 & 5 (Render PPTX in-place + Visual QA):
  - PoC Render: Ánh xạ dữ liệu mới trực tiếp vào `source.pptx` thông qua cơ chế edit-in-place (gán `run.text` giữ nguyên formatting, font size, bold, màu sắc, header bảng).
  - Visual QA: Rasterize slide sang PNG qua LibreOffice + `pdftoppm` ở chuẩn 1600x900, hiển thị trực quan Before/After trong notebook.
  - Overflow Check (theo OpenAI slide skill): Mở rộng slide với padding, kiểm tra biên ảnh -> Kết quả: `PASS — không tràn khung`.

3. ĐÁNH GIÁ REPO LIÊN QUAN: DeckUpdateBench (XiaoZhou2024/DeckUpdateBench)
================================================================================

Qua tìm hiểu repository `XiaoZhou2024/DeckUpdateBench` của cùng tác giả:

1. Mối liên hệ với đề tài:
   - Đây chính là **bản nâng cấp mở rộng trực tiếp** từ DynaSlide/SlideAgent (từ bài toán cập nhật 1 slide đơn lẻ lên **multi-page report decks**).
   - Tác giả xây dựng benchmark và agent (DeckAgent) phục vụ cho bài báo tiếp theo (hiện đang under review).

2. Những điểm tiến bộ vượt bậc của DeckUpdateBench:
   - **Dataset Builder hoàn chỉnh**: Có sẵn 47 bộ template packs chuẩn (`tpl_01` đến `tpl_48`, thiếu `tpl_16`) trong ngành bất động sản (thị trường tổng quan, nhà mới, thứ cấp, giá bán, cung-cầu, phân khúc cao cấp/bình dân...).
   - **Cơ chế sinh dữ liệu cặp (Source-Target)**: Tự động hóa việc sinh `source.pptx`, `instruction.json`, `target.pptx`, `source.json`, `target.json` qua ma trận tham số và PostgreSQL.
   - **Hệ thống đánh giá phân tầng**: Định nghĩa rõ ràng 3 cấp độ metric:
     • Task Success Rate (TSR — toàn bộ deck)
     • Page Success Rate (PSR — từng trang slide)
     • Element-Level Accuracy (từng shape / table / chart / text)

3. Điểm hạn chế chí mạng (Vẫn tồn tại ở cả SlideAgent và DeckUpdateBench):
   - Cả SlideAgent lẫn DeckAgent (trong DeckUpdateBench) **ĐỀU DỪNG LẠI Ở DẠNG DỮ LIỆU CẤU TRÚC (JSON/YAML)**, chưa có module write-back để xuất ra file `.pptx` hoàn chỉnh!
   - Trích dẫn trực tiếp từ README của DeckUpdateBench:
     > "The current CLI serializes the recovered report state, instruction patch, and element-level update plan to JSON. It does not export a rewritten PPTX in this repository snapshot."

4. Ý nghĩa đối với hướng nghiên cứu của nhóm:
   - Việc chúng ta kết hợp **agent-skill (in-place PPTX rendering + Visual QA)** chính là mảnh ghép còn thiếu quan trọng nhất để khép kín chu trình I/O end-to-end mà cả 2 repo của tác giả chưa làm được.
   - Chúng ta hoàn toàn có thể tận dụng bộ **Dataset Builder và 47 Template Packs của DeckUpdateBench** làm môi trường benchmark chuẩn cho các thử nghiệm ở giai đoạn tiếp theo (Week 4-7).
